# ① 핵심 사용자 정의

- 문서 상태: 확정 v1.0
- 적용 범위: 애퐁당패밀리 숏폼 제작 웹앱
- 설계 원칙: 최소 권한, 역할 겸임 허용, 승인 3종 분리, 모든 판단과 변경 이력 기록

## 1. 사용자 모델

웹앱의 사용자는 계정 하나에 하나 이상의 역할을 부여하는 방식으로 설계한다. 실제 1차 운영은 `콘텐츠 담당자 1명`과 `콘텐츠 팀장 1명`을 중심으로 한다. 다만 `제작·비용 승인`, `최종 영상 승인`, `배포 승인`은 서로 다른 권한·상태·이력으로 관리하며, 한 사람이 여러 승인 권한을 갖더라도 각 승인을 별도로 실행하고 사유를 남겨야 한다.

### 확정된 운영 구조

| 실제 사용자 | 겸임 역할 | 승인 권한 | 주 사용 기기 |
|---|---|---|---|
| 콘텐츠 담당자 | 기획자, 제작자, 검수자 | 제작·비용 승인 | 회사 PC |
| 콘텐츠 팀장 | 최종 영상 확인자, 배포 확인자 | 최종 영상 승인, 배포 승인 | 회사 PC, 모바일 승인 |

임직원만 접근할 수 있으며, 제작·편집 화면은 회사 PC를 우선 지원하고 팀장의 승인 화면은 모바일에서도 완전하게 사용할 수 있어야 한다.

## 2. 승인 담당자의 세부 역할

`승인 담당자`는 화면과 권한 체계에서 다음 세 하위 역할로 분리한다.

| 승인 유형 | 결정 내용 | 승인 전 필수 확인 | 승인으로 열리는 기능 |
|---|---|---|---|
| 제작·비용 승인자 | 선택된 스토리보드와 예상 비용으로 유료 영상을 생성해도 되는가 | 선택안, 사전 검수 상태, 공식 PNG 연결, 예상 비용·크레딧·클립 수·재생성 한도 | 승인된 버전에 한해 유료 영상 생성 |
| 최종 영상 승인자 | 특정 영상 버전을 공식 최종본으로 확정해도 되는가 | 영상 자동 검수, 실제 영상 재생 확인, 캐릭터/자막/저작권, 수정 이력 | 해당 버전을 `최종 승인본`으로 고정하고 배포안 작성 |
| 배포 승인자 | 특정 최종본을 지정 플랫폼·계정·일시·문구로 외부 공개해도 되는가 | 최종 영상 승인, 배포안, 플랫폼/계정, 예약 시각, 캡션·태그, 변경 여부 | 승인 범위에 한해 게시 또는 예약 |

승인 후 대상 버전, 비용, 캡션, 플랫폼, 게시 시각 등 승인 범위가 바뀌면 기존 승인을 자동 무효화하고 재승인을 요청한다.

## 3. 역할별 홈 화면의 첫 행동

| 역할 | 첫 화면의 1순위 | 대표 기본 버튼 |
|---|---|---|
| 기획자 | 작성 중이거나 수정 요청된 프로젝트 | `입력 이어서 작성` / `수정 후 재제출` |
| 제작자 | 내게 배정된 다음 제작 단계와 잠금 사유 | `시나리오 작성` / `스토리보드 제작` / `승인된 영상 생성` |
| 검수자 | 새 검수·재검수 대기 목록과 실패 위험 | `검수 시작` |
| 승인 담당자 | 본인 권한에 해당하는 승인 대기만 분리 표시 | `근거 확인 후 승인 검토` |
| 배포 담당자 | 배포 승인 상태와 가까운 예약 일정 | `배포안 작성` / `승인된 예약 실행` |
| 관리자 | 연동 오류, 비용 한도, 권한 변경, 가이드 버전 상태 | `운영 문제 확인` |

## 4. 초보 사용자 안내 체계

안내는 역할별로 다르지만 공통적으로 다음 구조를 유지한다.

1. **현재 위치**: 상단에 `현재 단계`, 전체 진행률, 담당자, 상태를 표시한다.
2. **다음 행동**: 화면마다 가장 중요한 기본 버튼은 하나만 강조하고, 완료 조건을 버튼 가까이에 둔다.
3. **잠금 설명**: 실행 불가 버튼을 숨기지 않고 비활성 상태로 보여 주며, 무엇이 충족되어야 열리는지 설명한다.
4. **입력 도움**: 쉬운 용어, 좋은 예/피해야 할 예, 기본값, 글자 수·파일 형식 검증을 제공한다.
5. **결정 요약**: 제출·승인·생성·게시 전에는 대상 버전, 비용, 영향, 되돌리는 방법을 한 번에 보여 준다.
6. **실패 복구**: 오류 코드보다 원인, 영향, 사용자가 할 수 있는 다음 행동을 먼저 제시한다.
7. **인수인계 요약**: 각 단계 완료 시 `결과물`, `결정 사항`, `다음 단계 입력값`, `담당자`를 자동 정리한다.

### 역할별 권장 안내 강도

- 기획자·제작자: 처음 3개 프로젝트 동안 상세 안내를 기본 표시하고, 이후 `간단히 보기`로 전환 가능
- 검수자·배포 담당자: 판정·게시 체크리스트와 위험 항목을 항상 표시
- 승인 담당자: 설명은 짧게 유지하되 승인 유형, 대상 버전, 금액, 외부 영향은 생략 불가
- 관리자: 고급 설정은 접어 두고, 변경 영향과 복구 가능 여부를 항상 표시

## 5. 권한 원칙

- 기본은 최소 권한이며 프로젝트별 역할 배정을 지원한다.
- 현재 운영 구조상 콘텐츠 담당자의 `제작·비용 자기 승인`은 허용한다. 단, 승인 화면에서 예상 비용·크레딧·클립 수·재생성 상한을 다시 확인하고 명시적으로 승인해야 한다.
- 실제 비용이 승인 금액 또는 재생성 상한을 초과하면 기존 제작·비용 승인을 자동 중지하고 콘텐츠 담당자가 수정된 금액을 다시 명시적으로 승인한다.
- 최종 영상 승인과 배포 승인은 콘텐츠 팀장만 실행할 수 있으며 콘텐츠 담당자는 대행할 수 없다.
- 검수자는 판정할 수 있지만 제작 산출물을 직접 덮어쓰지 않는다.
- 승인자는 승인 대상 버전을 직접 수정할 수 없다. 수정이 필요하면 반려 또는 수정 요청을 보낸다.
- 관리자는 승인 기록을 삭제할 수 없고, 정정 사유와 새 기록을 추가한다.
- 공식 가이드와 원본 레퍼런스는 확인한 사용자·일시·버전을 기록한다.
- 모든 생성 요청은 사용한 가이드 버전, PNG 레퍼런스, 모델, 프롬프트 계약 버전, 비용과 결과 버전에 연결한다.

## 6. 가장 먼저 설계할 핵심 사용자

### 1순위: 초보 콘텐츠 담당자

`기획자 + 제작자 + 검수자 + 제작·비용 승인자`를 겸하며 프로젝트 생성부터 영상 검수 요청까지 가장 자주 사용하는 콘텐츠 담당자를 첫 핵심 사용자로 선정한다.

선정 이유:

- 공식 명세의 운영 목표가 담당자 1인 중심의 효율화에 맞춰져 있다.
- 15단계 중 가장 많은 단계와 인수인계를 경험한다.
- 입력과 버전이 잘못되면 이후 검수·비용·영상·배포까지 오류가 전파된다.
- 생성형 도구에 익숙하지 않은 사용자도 복잡한 프롬프트 없이 이용해야 한다.
- 이 사용자의 `현재 단계와 다음 행동` 경험을 먼저 해결하면 다른 역할의 대기열과 승인 화면도 자연스럽게 정의된다.

첫 설계 페르소나는 다음과 같이 둔다.

> **콘텐츠 담당자 — 생성형 AI 초보**  
> 캐릭터 IP의 기본 업무는 이해하지만 생성 도구·프롬프트·영상 크레딧에는 익숙하지 않다. 기획·제작·검수와 제작비 승인을 혼자 처리하므로, 현재 단계와 다음 행동뿐 아니라 스스로 만든 결과를 다시 검수할 때 놓치기 쉬운 위험을 명확히 안내받아야 한다. 실수에 대한 가장 큰 걱정은 공식 가이드 위반, 승인 범위를 넘은 비용 발생, 잘못된 버전을 팀장에게 보내는 것이다.

### 후속 설계 순서

1. 콘텐츠 팀장 승인자: 모바일에서 최종 영상 승인과 배포 승인을 혼동 없이 처리
2. 배포 담당 기능: 승인 범위 내 게시·예약과 취소 처리
3. 관리자: 역할·연동·정책·감사 운영

## 7. 확정·제안·확인 필요 구분

### 확정 사항

- 제작·비용 승인, 최종 영상 승인, 배포 승인을 별도 상태와 이력으로 관리한다.
- 공식 가이드·원본 PNG 확인 여부와 버전을 기록한다.
- 승인 전 유료 생성과 승인 전 배포를 차단한다.
- 검수 판정은 통과·조건부 통과·실패 및 근거를 포함한다.
- 변경, 검수, 승인, 비용, 생성, 배포 이력을 삭제하지 않고 추적한다.

### 설계 제안

- 첫 핵심 사용자는 `초보 콘텐츠 담당자(기획+제작+검수+제작·비용 승인 겸임)`로 둔다.
- 제작·비용 자기 승인은 허용하되 승인 범위 초과 시 팀장 확인으로 전환한다.
- 역할은 계정 단위가 아니라 프로젝트 단위로도 배정할 수 있게 한다.
- 승인 범위가 변경되면 기존 승인을 무효화하고 재승인을 요구한다.

### 확정된 추가 사항

- 콘텐츠 담당자 1명이 기획·제작·검수를 담당한다.
- 콘텐츠 담당자가 제작·비용 승인을 담당한다.
- 콘텐츠 팀장이 최종 영상 승인과 배포 승인을 담당한다.
- 임직원만 사용하며 회사 PC 중심, 팀장 승인 기능은 모바일도 지원한다.
