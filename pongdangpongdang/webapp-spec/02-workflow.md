# ② 워크플로우 정의

- 문서 상태: 확정 v1.0
- 적용 조직: 콘텐츠 담당자 1명 + 콘텐츠 팀장 1명
- 핵심 원칙: 단계, 검수, 승인을 분리하고 승인 대상 버전이 바뀌면 기존 승인을 무효화한다.

## 1. 담당 구조

| 구분 | 담당 |
|---|---|
| 기획·시나리오·스토리보드·영상 제작 | 콘텐츠 담당자 |
| 기획·캐릭터·스토리·기술 검수 확인 | 자동 검수 + 콘텐츠 담당자 |
| 스토리보드 선택 | 콘텐츠 담당자 |
| 제작·비용 승인 | 콘텐츠 담당자 |
| 최종 영상 승인 | 콘텐츠 팀장 |
| 배포안 작성·게시·예약 실행 | 콘텐츠 담당자 |
| 배포 승인 | 콘텐츠 팀장 |
| 시스템·연동·감사 로그 관리 | 관리자 또는 시스템 자동 처리 |

## 2. 상태 설계 원칙

프로젝트에 하나의 거대한 상태값만 두지 않고 다음 네 축을 분리한다.

1. `current_stage`: 사용자가 현재 작업해야 하는 단계
2. `stage_status`: 해당 단계의 작성·실행 상태
3. `review_status`: 기획 검수와 영상 검수의 판정
4. `approval_status`: 제작·비용, 최종 영상, 배포 승인의 독립 상태

이 구조를 사용하면 예를 들어 프로젝트는 `영상 생성 단계`에 있으면서 동시에 `제작 승인=승인`, `영상 검수=시작 전`, `배포 승인=요청 전` 상태를 정확하게 표현할 수 있다.

### 공통 상태 어휘

| 구분 | 시스템 값 | 사용자 표시 |
|---|---|---|
| 단계 | `not_started` | 시작 전 |
| 단계 | `in_progress` | 작업 중 |
| 단계 | `waiting` | 담당자 대기 |
| 단계 | `blocked` | 진행 중단 |
| 단계 | `completed` | 단계 완료 |
| 단계 | `cancelled` | 취소됨 |
| 검수 | `not_started` | 검수 전 |
| 검수 | `passed` | 통과 |
| 검수 | `conditional` | 조건부 통과 |
| 검수 | `failed` | 실패 |
| 검수 | `needs_confirmation` | 담당자 확인 필요 |
| 승인 | `not_requested` | 요청 전 |
| 승인 | `pending` | 승인 대기 |
| 승인 | `approved` | 승인됨 |
| 승인 | `partial_revision` | 수정 요청 |
| 승인 | `regenerate` | 재생성 요청 |
| 승인 | `hold` | 보류 |
| 승인 | `discarded` | 폐기 |

`조건부 통과`는 자동 진행 허가가 아니다. 수정 항목의 심각도에 따라 콘텐츠 담당자가 수정 완료를 표시하고 재검수를 통과해야 다음 승인 단계로 이동한다.

## 3. 정상 흐름

| 단계 | 상태 전이 | 담당자 | 입력물 | 산출물 | 완료 조건 | 중단 조건 |
|---:|---|---|---|---|---|---|
| 1. 입력 검증 | `입력 중 → 검증 통과` | 콘텐츠 담당자 + 시스템 | 주제, 캐릭터, 상황, 감정, 길이, 비율, 사용 도구, 선택 입력 | `request.json`, 누락·충돌 검사 결과 | 필수값 존재, 공식 6인만 선택, 60초 미만, 비율·출력 조건 유효 | 필수값 누락, 가이드와 충돌, 지원하지 않는 형식, 저작권 위험 입력 |
| 2. 공식 가이드 적용 | `확인 필요 → 적용 완료` | 콘텐츠 담당자 + 시스템 | 검증된 입력, 공식 PDF/페이지 PNG, 구조화 가이드 | 적용 가이드 버전, 확인 페이지, 대상 단계, 확인자·시각 | 등장 캐릭터별 소개·턴어라운드·사용 규칙 페이지 실제 확인 및 기록 | 원본 접근 불가, 필수 페이지 미확인, 가이드 버전 불명, 사용자 입력과 공식 설정 충돌 미해결 |

| 7. 스토리보드 선택 | `선택 대기 → A/B/C 선택 완료` | 콘텐츠 담당자 | A/B/C 비교, 검수 결과, 예상 클립 수 | 선택안, 선택 사유, 선택 버전 | 정확히 한 안 선택, 선택 사유 기록 | 검수 미통과, 선택 버전이 최신이 아님, 복수 선택 또는 미선택 |
| 8. 제작·비용 승인 | `승인 대기 → 승인됨` | 콘텐츠 담당자 | 선택안, 최종 프롬프트, 공식 PNG, 예상 비용·크레딧·클립 수·재생성 상한 | 명시적 제작·비용 승인 기록 | `explicit=true`, 비용 사용 승인, 선택안·예상 크레딧·클립 수·재생성 상한 모두 기록 | 사전 검수 실패, 공식 레퍼런스 누락, 비용 미산정, 승인 사유·범위 누락 |
| 9. 영상 생성 | `실행 가능 → 생성 중 → 초안 완료` | 콘텐츠 담당자 + 영상 생성 시스템 | 승인된 선택안·버전·프롬프트·PNG·비용 범위 | 장면별 클립, `draft.mp4`, 실제 비용·크레딧·오류 로그 | 모든 필수 클립 성공, MP4, 60초 미만, 기본 9:16·1080×1920 | 제작 승인 무효/누락, API 미연결, 비용·재생성 상한 초과, 필수 클립 실패 |

## 4. 승인 게이트

### 제작·비용 승인 게이트

다음 조건이 모두 참일 때만 `영상 생성` 버튼을 활성화한다.

- 기획 자동 검수 `passed`
- 콘텐츠 담당자의 스토리보드 A/B/C 중 하나 선택
- 선택안 버전과 승인 대상 버전 일치
- 모든 장면에 공식 PDF 기반 PNG 레퍼런스 연결
- 프롬프트 계약 검증 통과
- 예상 비용, 예상 크레딧, 생성 클립 수, 재생성 상한 기록
- 콘텐츠 담당자의 명시적 비용 사용 승인

### 최종 영상 승인 게이트

다음 조건이 모두 참일 때만 팀장에게 최종 승인 요청을 보낸다.

- 영상 자동 검수 `passed`
- 콘텐츠 담당자의 실제 영상 재생 확인
- 영상 버전과 SHA-256 해시 기록
- 실제 비용과 재생성 횟수 기록
- 실패 클립이 남아 있지 않음

최종 승인 후에만 승인된 동일 해시를 `final.mp4`로 확정한다.

### 배포 승인 게이트

다음 조건이 모두 참일 때만 `게시` 또는 `예약` 버튼을 활성화한다.

- 최종 영상 승인 `approved`
- 승인된 `final.mp4` 해시와 배포 대상 영상 해시 일치
- 플랫폼, 계정, 문안, 공개 범위, 예약 시각 기록
- 문안 해시 기록
- 콘텐츠 팀장의 명시적 배포 승인

영상, 문안, 플랫폼, 계정, 공개 범위 또는 예약 시각이 바뀌면 배포 승인을 즉시 무효화한다.

## 5. 예외 흐름

### 5.1 반려·수정·재검수

| 상황 | 상태 전이 | 처리 | 다음 단계 |
|---|---|---|---|
| 입력 검증 실패 | `검증 중 → 수정 필요` | 오류 필드와 수정 예시 표시, 입력값 유지 | 입력 검증 재실행 |
| 기획 검수 실패 | `검수 실패 → 수정 중` | 실패 근거가 발생한 가장 이른 산출물로 이동 | 관련 산출물 수정 후 기획 전체 재검수 |
| 기획 검수 조건부 통과 | `조건부 통과 → 수정 확인 대기` | 필수 수정 체크리스트 생성, 담당자가 항목별 완료 표시 | 자동 재검수 후 통과해야 선택 단계 진입 |
| 제작·비용 승인 수정 요청 | `pending → partial_revision` | 스토리보드·프롬프트·비용 산정 중 지정 항목만 수정 | 사전 검수 및 제작 승인 재요청 |
| 제작·비용 승인 재생성 | `pending → regenerate` | 선택안 또는 A/B/C 전체를 새 버전으로 생성 | 기획 자동 검수부터 재진행 |
| 최종 영상 수정 요청 | `pending → partial_revision` | 실패 장면이나 자막·음원 등 지정 부분 수정 | 영상 자동 재검수 후 최종 승인 재요청 |
| 최종 영상 재생성 요청 | `pending → regenerate` | 기존 초안은 보존하고 새 영상 버전 생성 | 비용 범위 확인 → 영상 생성 → 영상 검수 |
| 배포안 수정 요청 | `pending → partial_revision` | 캡션·플랫폼·시간 등 지정 항목 수정 | 배포 승인 재요청 |
| 보류 | `pending → hold` | 사유와 재검토 예정일 기록, 자동 실행 정지 | 담당자가 재개할 때 최신 상태 재검증 |
| 폐기 | `pending → discarded` | 파일을 자동 삭제하지 않고 폐기 사유와 버전 보존 | 새 프로젝트 복제 또는 종료 |

### 5.2 산출물 변경 시 하위 단계 무효화

| 변경한 항목 | 자동 무효화되는 항목 |
|---|---|
| 입력값 또는 등장 캐릭터 | 가이드 적용 기록 이후 모든 산출물·검수·승인 |
| 가이드 버전 또는 확인 페이지 | 기획안 이후 모든 산출물·검수·승인 |
| 기획안 | 시나리오, A/B/C, 기획 검수, 선택, 제작 승인, 영상 이후 단계 |
| 시나리오 | A/B/C, 기획 검수, 선택, 제작 승인, 영상 이후 단계 |
| 선택 스토리보드·장면·프롬프트·PNG | 기획 검수, 제작 승인, 영상 이후 단계 |
| 예상 비용·클립 수·재생성 상한 | 제작·비용 승인 |
| 영상 파일 | 영상 검수, 최종 승인, 배포안·배포 승인·게시 실행 |
| 배포 문안·플랫폼·계정·공개 범위·예약 시각 | 배포 승인과 아직 실행되지 않은 예약 |

무효화는 기록 삭제가 아니라 `stale` 표시와 새 버전 연결로 처리한다.

### 5.3 영상 생성 실패

1. 장면별 작업을 독립적으로 기록한다.
2. 성공 클립은 `locked`로 보존하고 실패 클립만 `partial_failed`로 표시한다.
3. 오류 원인, 외부 요청 ID, 소비된 크레딧, 재시도 가능 여부를 기록한다.
4. 재생성 상한 안이면 콘텐츠 담당자가 실패 클립만 재시도한다.
5. 상한을 넘으면 추가 유료 호출을 차단하고 수정된 예상 비용으로 제작·비용 재승인을 요구한다.
6. 필수 클립이 모두 성공하기 전에는 `draft.mp4` 완료로 전환하지 않는다.

API 전체 장애 시 상태는 `failed`가 아니라 복구 가능한 `blocked / 외부 서비스 오류`로 두고, 이미 만든 클립과 비용 기록을 유지한다.

### 5.4 비용 초과

| 발생 시점 | 처리 |
|---|---|
| 생성 전 예상 비용이 승인 한도 초과 | 영상 생성 버튼 잠금, 수정된 비용·크레딧·재생성 상한으로 제작·비용 재승인 |
| 생성 중 실제 비용이 승인 한도에 도달 | 다음 유료 호출 즉시 중단, 성공 클립 보존, 초과 예상액 표시 |
| 외부 도구가 예고 없이 초과 청구 | 추가 생성 중단, 실제 비용과 외부 요청 ID 기록, 관리자 알림 |

현재 조직 구조에서는 콘텐츠 담당자가 수정된 제작·비용 승인을 다시 실행한다. 수정 승인 전까지 추가 유료 호출은 잠긴 상태로 유지한다.

### 5.5 배포 실패·취소·철회

| 상황 | 상태 전이 | 처리 |
|---|---|---|
| 게시 API 실패 | `submitted/processing → failed` | 원격 오류와 재시도 가능 여부 기록, 같은 중복 방지 키로 상태 조회 후 안전 재시도 |
| 예약 전 취소 | `approved → cancelled` | 게시 호출 없이 취소 사유 기록, 배포 승인 사용 종료 |
| 플랫폼 예약 취소 | `scheduled → cancel_requested → cancelled` | 플랫폼 원격 예약 취소 성공 여부와 원격 ID 기록 |
| 일부 플랫폼만 실패 | 프로젝트는 `부분 완료` | 성공 플랫폼은 유지, 실패 플랫폼만 재시도 또는 취소 |
| 이미 게시된 콘텐츠 철회 | `published → withdrawal_pending → withdrawn/withdrawal_failed` | 팀장의 별도 명시적 철회 확인 후 삭제·비공개 API 실행, 기존 URL과 철회 사유 보존 |
| 배포 승인 후 문안·시간 변경 | `approved → stale → pending` | 기존 승인 무효화, 변경된 해시로 재승인 |

현재 제작 이력 스키마의 게시 상태에는 취소·철회 상태가 없으므로 `cancel_requested`, `cancelled`, `withdrawal_pending`, `withdrawn`, `withdrawal_failed`를 추가해야 한다.

## 6. 프로젝트 완료 조건

### 제작 완료

- 입력과 가이드 적용 이력 존재
- 기획안, 시나리오, A/B/C 스토리보드와 장면 PNG 존재
- 기획 자동 검수 통과
- 선택 스토리보드와 제작·비용 승인 존재
- 60초 미만 MP4 영상 존재
- 영상 자동 검수 통과
- 콘텐츠 팀장의 최종 영상 승인 존재
- 시간, 비용, 크레딧, 클립 수, 재생성 횟수, 버전 이력 기록

### 배포 포함 전체 완료

- 제작 완료 조건 충족
- 플랫폼별 배포안과 팀장 배포 승인 존재
- 승인된 모든 플랫폼이 `scheduled`, `published`, `cancelled` 또는 승인된 철회 종료 상태
- 원격 ID, URL, 영상·문안 해시, 처리 결과 기록

## 7. 사용자에게 보여 주는 다음 행동 규칙

각 상태는 항상 다음 네 문장으로 설명한다.

- **현재 상태:** 지금 어디까지 진행되었는지
- **중단 이유:** 왜 다음 버튼이 잠겼는지
- **해야 할 일:** 누가 무엇을 해야 하는지
- **완료되면:** 어떤 단계와 기능이 열리는지

예시:

> 현재 영상 생성이 중단되었습니다. 승인된 재생성 한도 2회를 모두 사용했습니다. 콘텐츠 담당자가 예상 추가 비용을 확인하고 제작·비용을 다시 승인하면 실패한 4번 클립만 재생성할 수 있습니다.

## 8. 확정·제안 구분

### 확정 사항

- 콘텐츠 담당자가 기획·제작·검수·제작비 승인을 담당한다.
- 콘텐츠 팀장이 최종 영상 승인과 배포 승인을 담당한다.
- 세 승인을 서로 다른 상태와 기록으로 관리한다.
- 승인 전 유료 영상 생성과 승인 전 게시·예약을 차단한다.
- 변경으로 승인 범위가 달라지면 기존 승인을 무효화한다.
- 실패한 영상 클립만 재생성하고 성공 클립은 보존한다.
- 비용 초과 시 콘텐츠 담당자가 수정된 금액을 다시 명시적으로 승인한다.
- 이미 게시된 콘텐츠는 팀장의 별도 철회 확인 후 삭제 또는 비공개 처리한다.

### 설계 제안

- 게시 이력 스키마에 취소·철회 상태를 추가한다.
