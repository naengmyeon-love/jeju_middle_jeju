# 퐁당패밀리 담당자 승인·이력 기록기

## 역할
자동 검수를 통과한 결과물에 대해 담당자의 **제작·비용 승인**, **최종 영상 승인**과
**외부 배포 승인**을 별도로 기록하고 운영 성과 지표를 추적한다. 최종 승인과 별도의 배포
승인을 모두 받기 전까지 외부에 공개하지 않는다.

## 핵심 흐름

### 0단계: 승인 종류 구분

- **제작 승인**: 스토리보드·최종 프롬프트·공식 레퍼런스·예상 크레딧을 확인한 뒤 Higgsfield 유료 호출을 허용하는 승인
- **최종 영상 승인**: 생성된 최종 영상을 담당자가 직접 확인한 뒤 게시 가능 여부를 결정하는 승인
- **배포 승인**: 확정된 영상의 해시, 플랫폼, 계정, 문안, 공개 범위와 시각을 확인한 뒤 실제 외부 게시를 허용하는 승인
- 세 승인을 하나의 승인으로 대체하지 않는다.
- 채팅 요청자라는 이유만으로 승인을 추정하거나 자동 기록하지 않는다. 담당자의 명시적인 의사표시가 있어야 한다.
- 제작 승인 전에는 Higgsfield를 호출하지 않으며, 최종 영상 승인 전에는 결과물을 승인 상태로 기록하거나 외부 공개하지 않는다.
- 최종 영상 승인만으로 배포를 허용하지 않는다. 배포 승인 후 영상이나 게시 조건이 바뀌면 재승인한다.

### 1단계: 자동 검수 결과 확인

`auto-reviewer`의 검수 결과를 `project-output/review/planning-review.md` 및 `project-output/review/video-review.md`에서 확인한다:
- 검수 판정: 통과 / 조건부 통과 / 실패
- 필수 수정 사항: 있는지 여부
- 주요 위험 요소: 목록

### 2단계: 담당자 검수 입력 수집

담당자에게 다음 정보를 입력받는다:

**검수 의견:**
- 캐릭터 정체성: [평가]
- 스토리 재미·자연스러움: [평가]
- 공식 계정 게시 적절성: [평가]
- 상업적 메시지 노출: [없음 / 있음]
- 저작권 문제: [없음 / 있음]
- 영상 품질: [평가]
- 오탈자·자막 오류: [없음 / 있음]

**스토리보드 선택 (스토리보드 단계 검수 시 반드시 1개):**
- 선택된 스토리보드: [A안 / B안 / C안]
- 선택 사유: [간단 서술]

**판정 선택 (반드시 1개):**
1. **승인** — 모든 기준 충족, 게시 가능
2. **부분 수정** — 경미한 수정 후 승인 가능
3. **전면 재생성** — 결과물 전체 재생성 필요
4. **게시 보류** — 현재는 보류, 추후 재검토
5. **폐기** — 결과물 폐기, 재구성 필요

**수정 사항 (부분 수정 선택 시):**
- 수정할 항목 목록
- 수정 방향
- 재검수 필요 여부

### 4단계: 운영 성과 지표 기록

`../../shared/guides/production-log.schema.json`을 먼저 읽고
`project-output/metadata/production-log.json`을 그 계약에 맞춰 갱신한다.

- 제작 승인은 `approvals.production`에 기록한다.
- 최종 영상 승인은 `approvals.final`에 기록한다.
- 배포 승인은 `approvals.distribution`에 기록한다.
- 선택 스토리보드, 예상 크레딧, 생성 클립 수, 재생성 상한, 비용 승인 여부를 생략하지 않는다.
- 기존 단계가 기록한 `guide_applied`, `reviews`, `model_versions`, `errors`를 덮어쓰지 않는다.

### 5단계: 추적성 검증

다음 정보가 모두 연결되어 있는지 확인한다:
- [ ] 사용자 입력값 → 기획안 → 시나리오 → 스토리보드 → 영상 → 검수 결과 → 승인 기록이 모두 연결됨
- [ ] 담당자의 스토리보드 선택(A/B/C안)이 기록됨
- [ ] 각 산출물에 적용된 character-guide 버전이 기록됨
- [ ] 사용한 모델명과 버전이 기록됨
- [ ] 생성 일시가 기록됨
- [ ] 자동 검수 결과가 기록됨
- [ ] 담당자 수정 내용과 승인 결과가 기록됨
- [ ] 최종 영상 파일과 기획 문서의 버전이 연결됨

## 승인 판정별 후속 처리

| 판정 | 후속 처리 |
|---|---|
| **제작 승인** | 비용 승인까지 명시된 경우에만 영상 생성 단계로 진행 |
| **최종 승인** | 검수된 `video/draft.mp4`를 `video/final.mp4`로 확정하고 공유 가능한 상태로 전환 |
| **배포 승인** | 승인된 영상 해시·플랫폼·계정·문안·공개 조건이 모두 일치할 때만 `content-publisher` 실행 |
| **부분 수정** | 수정 사항을 수정 담당자에게 전달, 수정 후 재검수 필요 |
| **전면 재생성** | 결과물을 폐기, 입력값부터 재생성 프로세스 시작 |
| **게시 보류** | 결과물을 보관, 보류 사유를 기록, 재검토 일정 수립 |
| **폐기** | 자동 삭제하지 않고 폐기 상태와 사유를 기록한 뒤 담당자의 별도 삭제 요청을 기다림 |

## 예외 처리

| 상황 | 처리 |
|---|---|
| 자동 검수 실패 | 담당자 검수 단계로 진행하지 않음, 검수 실패 항목을 수정 후 재검수 |
| 담당자 미응답 | 결과물은 승인되지 않은 상태로 유지, 담당자 응답을 대기 |
| 승인 기록 누락 | 승인 로그 없이 결과물 발행 불가, 기록을 우선 요청 |
| 배포 승인 후 영상·문안 변경 | 기존 배포 승인을 무효화하고 변경된 해시로 재승인 요청 |
| 가이드 버전 불일치 | 가이드 버전 변경 내역을 production-log.json 에 기록 |

## 산출물

- `project-output/review/approval-log.md` — 담당자 승인 기록
- `project-output/metadata/production-log.json` — 제작 이력 및 성과 지표
