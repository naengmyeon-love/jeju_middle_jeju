# 퐁당패밀리 숏폼 스토리보드 3안 자동 생성기

## 역할
시나리오(scenario.md)를 입력으로 받아 동일한 이야기를 **서로 다른 연출 방향**으로 해석한
스토리보드 3개를 만든다. 각 장면의 실제 이미지를 생성하고 Markdown 안에 스토리와 함께
삽입한다. 각 안은 카메라 구도, 타이밍, 장면 구성, 이미지와 연출 의도가 명확히 구분되어야 한다.

## 연출 방향 정의

| 안 | 콘셉트 | 핵심 특징 |
|---|---|---|
| **A안: 기본형** | 캐릭터와 대사가 명확하게 전달되는 안정적 연출 | 정면·중간 샷 위주, 대사 중심, 깔끔한 전환 |
| **B안: 코미디형** | 표정, 타이밍, 반전, 효과음을 강조한 연출 | 과장된 표정 클로즈업, 타이밍 컷, 효과음 강조, 배경 단순화 |
| **C안: 감성형 / 세계관 확장형** | 캐릭터 관계와 퐁당패밀리 세계관을 강조한 연출 | 환경 샷·와이드 샷 활용, 분위기 연출, 관계 시각화, 색상 그라데이션 |

## 핵심 흐름

### 1단계: 시나리오 분석

`project-output/planning/scenario.md`를 읽고 각 장면별 다음 정보를 추출한다:
- 시간 구간
- 배경
- 등장 캐릭터
- 행동·표정
- 대사·자막
- 효과음·음악
- 장면 전환

### 2단계: 스토리보드 A안 (기본형) 생성

**연출 콘셉트:** 기본형은 **정보 전달의 명확성**에 초점을 둔다. 시청자가 캐릭터, 대사, 상황을 한눈에 이해할 수 있도록 구성한다.

- 카메라: 정면·중간 샷 중심, 안정적인 구도
- 전환: 페이드·인, 자연스러운 연속 동작
- 자막: 대사를 그대로 자막화, 화면 하단 중앙
- 효과음: 핵심 행동음만 선별, 과장 없이
- BGM: 가벼운 배경, 대사 가리지 않음
- 타이밍: 시나리오 시간을 그대로 따름

**템플릿:**

```markdown
# 스토리보드 A안 — 기본형

## 연출 방향

- 연출 콘셉트: 캐릭터와 대사가 명확하게 전달되는 안정적 연출
- 목표 감정: 편안함, 이해 용이
- 총 길이: [초]
- 장면 수: [N]

| 장면 | 시간 | 화면 구성 | 캐릭터 행동·표정 | 대사·자막 | 카메라 | 효과음·음악 | 생성 프롬프트 |
|---|---:|---|---|---|---|---|---|
| 1 | 0~3초 | [화면 구성 설명] | [행동·표정] | `[대사]` / [자막] | [카메라 구도] | [효과음] / [BGM] | [영상 생성용 프롬프트] |
| 2 | 3~8초 | ... | ... | ... | ... | ... | ... |
```

### 3단계: 스토리보드 B안 (코미디형) 생성

**연출 콘셉트:** 코미디형은 **표정, 타이밍, 반전, 효과음**을 강조한다. 시청자의 웃음과 반응을 이끌어내는 연출을 구성한다.

- 카메라: 과장된 표정 클로즈업, 급격한 줌·팬, 예측 불가한 앵글
- 전환: 점프컷, 급격한 타이밍 변화, 예상치 못한 컷
- 자막: 대사 + 강조 자막 (의성어·의태어, 말풍선)
- 효과음: 웃음 포인트에 맞춘 효과음 집중, 타이밍 컷에 맞는 효과음
- BGM: 경쾌·유머러스, 반전 시 음악 변화
- 타이밍: 시나리오 시간을 코미디 리듬에 맞게 재배분 (빠른 컷, 일시 정지)

**템플릿:** (컬럼 동일, 내용 상이)

```markdown
# 스토리보드 B안 — 코미디형

## 연출 방향

- 연출 콘셉트: 표정, 타이밍, 반전, 효과음을 강조한 연출
- 목표 감정: 웃음, 놀라움, 반전 재미
- 총 길이: [초]
- 장면 수: [N]

| 장면 | 시간 | 화면 구성 | 캐릭터 행동·표정 | 대사·자막 | 카메라 | 효과음·음악 | 생성 프롬프트 |
|---|---:|---|---|---|---|---|---|
| 1 | 0~2초 | [과장된 표정 클로즈업] | [강한 표정 변화] | `"[대사]"` / **[강조 자막]** | [급격한 줌인] | [부딪히는 소리] / [경쾌한 BGM] | [영상 생성용 프롬프트] |
```

### 4단계: 스토리보드 C안 (감성형/세계관 확장형) 생성

**연출 콘셉트:** 감성형/세계관 확장형은 **캐릭터의 관계와 세계관의 분위기**를 강조한다. 퐁당패밀리의 일상과 세계관을 시각적으로 풍부하게 표현한다.

- 카메라: 와이드 샷, 환경 샷, 슬로우 팬, 슬로우 줌
- 전환: 부드러운 디졸브, 매치 컷, 환경 연속성
- 자막: 대사 + 세계관 설명 자막 (필요 시), 감성적인 폰트 스타일
- 효과음: 환경음(바람, 새소리, 자연음), 감정선 맞는 효과음
- BGM: 감성·분위기 중심, 캐릭터 관계에 맞춘 멜로디
- 타이밍: 여백을 살린 느린 페이스, 감정 호흡을 위한 일시 정지

**템플릿:** (컬럼 동일, 내용 상이)

```markdown
# 스토리보드 C안 — 감성형 / 세계관 확장형

## 연출 방향

- 연출 콘셉트: 캐릭터 관계와 퐁당패밀리 세계관을 강조한 연출
- 목표 감정: 따뜻함, 공감, 세계관 몰입
- 총 길이: [초]
- 장면 수: [N]

| 장면 | 시간 | 화면 구성 | 캐릭터 행동·표정 | 대사·자막 | 카메라 | 효과음·음악 | 생성 프롬프트 |
|---|---:|---|---|---|---|---|---|
| 1 | 0~5초 | [환경 와이드 샷, 세계관 배경] | [일상적 행동] | `"[대사]"` / [자막] | [슬로우 팬] | [환경음] / [감성 BGM] | [영상 생성용 프롬프트] |
```

### 5단계: 장면 이미지 생성

1. **장면 프롬프트는 직접 쓰지 않는다.** `higgsfield-prompt-builder` skill로 조립한다. 그 스킬이 자기 폴더의 `references/image-generation-contract.json` 계약을 적용한다. 그 스킬이 계약을 읽지 못해 중단하면, 여기서도 장면 이미지를 만들지 않는다.
   - 실제 조립은 `node unsorted/scripts/build-pongdang-prompt.mjs ... --command`가 수행한다.
   - **위 표의 `카메라` 칸을 그대로 넘기지 않는다.** 그 칸은 영상 연출용이라 트래킹·패닝·전환이 들어 있고, 정지 이미지 모델은 지시 하나당 컷 하나를 그린다(실측 4/4). 조립기가 거부한다.
   - 장면마다 **가장 중요한 한 순간**을 골라 단일 앵글로 다시 쓴다. 예: `low-angle full shot`, `front-facing close-up`.
   - 두 순간이 모두 필요하면 장면을 둘로 나눈다. 스토리보드의 카메라 칸은 영상 생성용으로 원문 그대로 남겨 둔다.
2. `../../shared/references/WORKFLOW_GUIDE.md`와 등장 캐릭터별 소개·턴어라운드·사용 규칙 PNG를 `view_image`로 실제 확인한다.
3. 단체 장면은 `page-03.png`, `page-05.png`, `page-07.png`도 확인한다.
4. 안별·장면별로 이미지 한 장을 생성한다. 서로 다른 장면이나 안을 한 번의 호출로 묶지 않는다.
5. 모든 캐릭터 이미지는 관련 공식 페이지 PNG를 레퍼런스 이미지로 전달한다(Higgsfield는 `--image`, 내장 도구는 `referenced_image_paths`). 텍스트 프롬프트만으로 캐릭터를 새로 만들지 않는다. 레퍼런스를 붙이지 못하면 그 장면은 생성하지 않는다.
6. 첫 장면 이후에는 공식 페이지와 직전 승인 장면 이미지를 함께 참조하여 캐릭터 외형·배경·소품의 연속성을 유지한다. 공식 원본과 직전 장면이 충돌하면 공식 원본을 따른다.
7. 생성 결과를 workspace의 아래 경로에 저장한다.

```text
project-output/storyboard/images/
├── a/scene-01.png
├── a/scene-02.png
├── b/scene-01.png
└── c/scene-01.png
```

이미지는 세로형 9:16 구도를 기본으로 하고, 캐릭터와 주요 행동이 안전 영역 안에 들어오게 한다.
대사·자막·말풍선은 이미지에 굽지 않는다. 텍스트는 Markdown에 정확히 표기한다.
워터마크, 임의 로고, 임의 HEX 색상과 공식에 없는 캐릭터 요소를 넣지 않는다.

### 6단계: 이미지와 스토리 결합

기존 요약 표 다음에 아래 형식의 장면별 이미지 보드를 작성한다. 이미지 파일이 실제로 존재할 때만 링크한다.

```markdown
## 장면별 이미지 보드

### 장면 1 · 00:00~00:03

![A안 장면 1 — 부라봉이 마당을 바라보는 오프닝](images/a/scene-01.png)

- **스토리:** [이 장면에서 벌어지는 사건과 다음 장면으로 이어지는 이유]
- **화면:** [배경과 화면 구성]
- **캐릭터:** [행동과 표정]
- **대사·자막:** "[대사]" / [자막과 위치]
- **카메라:** [구도와 움직임]
- **효과음·음악:** [효과음과 BGM]
- **영상 생성 프롬프트:** [최종 영상용 프롬프트]
- **이미지 생성 기록:** [사용한 공식 페이지와 이미지 생성 도구]
```

이미지 생성이 실패하면 빈 링크나 임의 placeholder를 넣지 않는다. 실패 원인과 재시도 가능 여부를
기록하고 해당 장면을 `이미지 생성 대기`로 표시한다.

### 7단계: 이미지 자체 검수

각 이미지를 `view_image`로 다시 열고 다음을 확인한다.

- [ ] 이미지 파일이 존재하고 Markdown에서 열리는가
- [ ] **화면이 한 프레임인가** (분할 컷·상하 2단·격자·테두리가 없는가)
- [ ] **요청한 캐릭터가 각각 정확히 한 번만 등장하는가** (같은 캐릭터가 두 번 그려지지 않았는가)
- [ ] 공식 외형·실루엣·비율·고유 장식이 유지되는가
- [ ] 양퐁당 동백 우측, 냥냥이 눈 반점 좌측이 유지되는가
- [ ] 단체 장면 키 순서와 관계 극성이 맞는가
- [ ] 장면 설명과 이미지의 행동·표정·배경·카메라가 일치하는가
- [ ] A/B/C안 이미지의 구도와 톤이 실제로 다른가
- [ ] 이미지 내부에 깨진 문자·대사·워터마크가 없는가
- [ ] 앞뒤 장면에서 캐릭터 외형과 배경이 불필요하게 흔들리지 않는가

공식 규칙 위반이면 해당 이미지만 한 번에 한 가지 수정사항으로 재생성하고 다시 확인한다.
원본만으로 판단할 수 없는 표현은 생성하지 말고 담당자 확인 필요로 표시한다.

### 8단계: 3안 차별화 검증

3개 안을 생성한 후 아래 사항을 반드시 확인한다:

- [ ] A·B·C안의 **카메라 구도**가 서로 다른가
- [ ] **장면 구성**(샷 수, 시간 배분, 전환 방식)이 다른가
- [ ] **연출 의도**(목표 감정, 톤)가 명확히 구분되는가
- [ ] **효과음·BGM 선택**이 각 콘셉트에 부합하는가
- [ ] **생성 프롬프트**가 각 연출 방향에 맞게 다른가
- [ ] 장면 이미지의 구도·표정·배경 연출이 각 안에 맞게 실제로 다른가
- [ ] 단순 문장 치환이 아닌가 (같은 장면을 단어만 바꾼 것은 불합격)

## 가이드라인
- 각 스토리보드의 **생성 프롬프트** 컬럼에는 장면별 영상 생성을 위한 상세 프롬프트를 작성한다 (캐릭터 외형, 배경, 행동, 카메라, 조명, 분위기 포함).
- 장면 이미지는 `higgsfield-prompt-builder`로 만든 프롬프트와 공식 레퍼런스로 한 장씩 생성하고 프로젝트 폴더에 저장한다.
- 생성한 장면 이미지의 최종 저장 경로, 프롬프트와 참조한 공식 페이지를 제작 이력에 기록한다.
- **`character-guide` 스킬의 `SKILL.md`를 Read 한 뒤**, §4의 외형 O/X 규칙과 §2 세계관을 생성 프롬프트에 정확히 반영한다.
- ⚠️ **공식 색상 HEX는 미확보 상태다**(character-guide §9-1). HEX 값을 임의로 만들어 넣지 말고, `character-guide` §4의 서술형 색상 표기(예: "주황 한라봉 몸체, 초록 꼭지와 잎, 양쪽 진한 주황 볼")를 그대로 사용한다.
