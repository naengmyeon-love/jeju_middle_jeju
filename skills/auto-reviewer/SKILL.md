# 퐁당패밀리 자동 품질 검수기

## 역할
생성된 콘텐츠 결과물을 **공식 가이드라인** 기준으로 자동 검사하여, 각 항목에 대한 **통과/조건부 통과/실패** 판정과 근거를 출력한다. 검수 결과는 담당자 최종 검수의 입력 자료로 활용된다.

**판정 근거는 반드시 `character-guide` 스킬의 `SKILL.md`에서 인용한다.** 검수를 시작하기 전에 이 파일을 Read 하고, 위반 지적 시 해당 절 번호(예: §4.3, §5.1)를 함께 제시한다.

**라벨에 따른 판정 강도** (character-guide §0 신뢰도 라벨)

| 라벨 | 위반 시 처리 |
|---|---|
| `[공식]` | 실패 또는 자동 실패 |
| `[구조화]` | 조건부 통과 |
| `[운영]` | 조건부 통과 + "운영 규칙 기준"임을 명시 |
| `[확인필요]` | 판정하지 않고 "담당자 확인 필요"로 표시 |

### 1. 캐릭터 검수

| 공식 외형 일치 | 신체 특징·무늬 위치·방향이 O/X 규칙과 일치하는가 | §4 각 절 | ✅ 자동 실패 |
| 성격 유지 | 캐릭터 행동이 공식 프로필과 일치하는가 | §4 프로필 | ✅ 자동 실패 |
| 말투 일관성 | 대사 어미가 아래 §말투 판정표와 일치하는가 | §4 말투 | ✅ 자동 실패 |
| 관계 일치 | 관계와 **극성(긍정/중립/부정)** 이 관계표와 일치하는가 | §5.1 | ✅ 자동 실패 |

| 비율 변경 | 얼굴 비율·신체 비율이 변경되지 않았는가 | §3.2 | ✅ 자동 실패 |

| **호꼬 무언** | 호꼬에게 대사가 부여되지 않았는가 | §4.5 | ✅ 자동 실패 |
| **부라봉 기억상실** | 기억상실 이전 과거를 확정하지 않았는가 | §4.1 | ✅ 자동 실패 |
| **부정 관계 보존** | 공식 부정 관계를 훈훈하게 미화하지 않았는가 | §5.4 | ✅ 자동 실패 |
| 무대 구분 | 고르방의 집 / 할머니의 귤밭을 혼동하지 않았는가 | §2.2 | 조건부 통과 |
| 색상 지시 | 임의 생성한 HEX 값을 사용하지 않았는가 | §1, §9-1 | ✅ 자동 실패 |

#### 말투 판정표 `[공식]`

| 캐릭터 | 기대 어미/화법 | 판정 |
|---|---|---|
| 부라봉 | `~다봉` / `~라봉` / `~냐봉` / `~다봉봉` | 어미 불일치 시 실패 |
| 냥냥이 | `~냥` / `~다냥` | 어미 불일치 시 실패 |
| 양퐁당 | `~양` + 짧은 돌직구·팩폭 | 어미 불일치 시 실패 |
| 구애구 | `~라구` | 어미 불일치 시 실패 |
| 고르방 | **고정 어미 없음.** 말이 길고 수다스러운 화법, 아재개그 | **어미를 창작해 붙였으면 실패.** 화법 불일치는 조건부 통과 |
| 호꼬 | **대사 없음.** 의성어·표정·행동·자막으로 표현 | **대사가 있으면 자동 실패** |

## 작동 방식

### 0단계: 공식 가이드 로드

공식 원본 확인 기록, `../../shared/guides/character-guide.md`, `.json`, `character-guide` skill을 Read 한다. 읽지 못하면 검수를 수행하지 않고
"공식 가이드를 읽을 수 없어 검수를 수행할 수 없습니다"를 반환한다.
가이드 버전(예: v2.0)을 검수 결과에 기록한다.

### 1단계: 검수 대상 확인

검수 대상 파일의 존재와 형식을 확인한다:
- `project-output/planning/plan.md` — 기획안
- `project-output/planning/scenario.md` — 시나리오
- `project-output/storyboard/storyboard-{a,b,c}.md` — 스토리보드
- `project-output/storyboard/images/{a,b,c}/scene-NN.png` — 장면 이미지
- `project-output/video/draft.mp4` — 승인 전 영상
- `project-output/video/final.mp4` — 최종 승인 영상

해당 단계의 필수 파일이 없으면 스킵하지 말고 `실패`로 판정하여 누락된 파일명을 기록한다.

### 2단계: 항목별 검수 수행

각 검수 카테고리의 항목을 순차적으로 검사한다. 검사 방법은 다음과 같다:

**텍스트 기반 검수 (기획안·시나리오·스토리보드):**
- 키워드 매칭: 금지어 목록 (구매, 할인, 가격, 판매, 링크, 클릭 등) 검색
- 템플릿 구조 검증: 필수 섹션·필드가 모두 채워져 있는지 확인
- 시간 합산: 장면별 시간을 합산하여 60초 미만인지 확인
- 말투 패턴 검사: 위 **말투 판정표** 기준으로 캐릭터별 어미를 검사. 호꼬 대사 존재 여부를 별도 확인
- 캐릭터 이름 일관성: 등장 캐릭터가 공식 6인 목록과 일치하는지 확인
- 금칙 서술 검사: "해녀 양퐁당", 양퐁당의 물질/잠수/수영, 호꼬 대사, 부라봉 과거 확정, 임의 HEX(`#`로 시작하는 6자리 색상값) 검색

**스토리보드 이미지 검수:**
- 각 Markdown의 장면 수와 대응 이미지 파일 수를 비교
- Markdown 이미지 링크가 실제 파일을 가리키는지 확인
- 각 PNG를 `view_image`로 열어 공식 페이지와 외형·무늬 방향·키 비례를 시각 비교
- 장면 텍스트와 이미지의 등장 캐릭터·행동·표정·배경·카메라를 비교
- 같은 안의 인접 장면과 캐릭터 외형·배경·소품 연속성을 비교
- A/B/C안의 구도와 연출 차이가 이미지에도 나타나는지 비교
- 깨진 문자·대사·워터마크·임의 로고가 보이면 실패 처리

**영상 기반 검수 (MP4):**
- 파일 형식 검증: 확장자 및 컨테이너 검증
- 길이 측정: `ffprobe` 등으로 길이 추출
- 해상도·비율 확인: 메타데이터 추출
- 자막 위치: 자막 트랙의 위치 정보 확인 (가능한 경우)
- 오디오 트랙 존재 여부: 음성 트랙이 있는지 확인

### 3단계: 판정 산출

#### 종합 판정 규칙

- **통과**: 모든 필수 기준을 충족함
- **조건부 통과**: 경미한 수정 후 제작 또는 게시 가능
- **실패**: 캐릭터 훼손, 상업성 노출, 저작권 위험 등 중대한 문제가 있음

**자동 실패 트리거** — 다음 항목 중 하나라도 실패하면 최종 판정은 자동으로 `실패`:

1. 캐릭터 공식 외형 훼손
2. 캐릭터 성격 또는 말투의 중대한 불일치
3. 양퐁당을 해녀로 묘사하거나 물질·잠수·수영 장면 포함
4. 호꼬에게 대사 부여
5. 부라봉의 기억상실 이전 과거를 확정
6. 공식 부정 관계를 긍정 관계로 변경
7. 공식 6인 외 캐릭터 등장
8. 임의로 생성한 공식 색상 HEX 사용
9. 필수 스토리보드 장면 이미지 누락 또는 이미지·스토리의 중대한 불일치
10. 직접적인 상품 판매 또는 구매 유도
11. 영상 길이 60초 이상
12. 저작권 침해 가능성이 높은 요소 포함
13. 담당자 검수 누락 (필수 검수 항목이 완료되지 않은 경우)

### 4단계: 결과 출력

아래 형식의 Markdown 으로 검수 결과를 출력한다:

```markdown
# 자동 검수 결과

## 종합 결과

- 판정: [통과 / 조건부 통과 / 실패]
- 총점: [N/M]
- 필수 수정 여부: [있음 / 없음]
- 주요 위험 요소: [위험 요소 목록 or "없음"]

## 상세 검수

| 검수 항목 | 결과 | 근거 | 수정 제안 |
|---|---|---|---|
| 영상 길이 | 통과 | 예상 길이 32초 | 없음 |
| 캐릭터 말투 | 실패 | 장면 3의 어미가 공식 말투와 다름 | 공식 어미로 수정 |
| 상업성 노출 | 통과 | 구매 유도 문구 없음 | 없음 |
```

## 검수 템플릿 (`review/planning-review.md`)

검수 결과는 다음 폴더에 저장한다:
- `project-output/review/planning-review.md` — 기획·시나리오 단계 검수 결과
- `project-output/review/video-review.md` — 영상 단계 검수 결과

## Higgsfield 호출 전 사전 검수

`planning-review.md`에는 아래 항목을 별도 게이트로 기록한다. 하나라도 실패하거나 확인되지 않으면 판정을 `생성 중단`으로 표시하고 Higgsfield를 호출하지 않는다.

- 기획안·시나리오·선택 스토리보드가 자동 검수를 통과했는가
- 담당자가 스토리보드를 명시적으로 선택했는가
- 각 장면에 공식 PDF 기반 캐릭터 레퍼런스 또는 공식 원화 기반 고정 시작 이미지가 연결되었는가
- 텍스트 프롬프트만으로 캐릭터를 새로 생성하는 장면이 없는가
- 최종 프롬프트의 등장 캐릭터 수·외형·무늬 방향·키 비례가 공식 가이드와 일치하는가
- 최종 프롬프트가 `higgsfield-prompt-builder`의 블록 순서(STYLE·CAST·SCENE·COMPOSITION·NEGATIVE·OUTPUT)를 따르는가
- CAST 블록이 `higgsfield-prompt-builder/references/image-generation-contract.json`의 `lock_en`과 문자 그대로 일치하는가 (요약·의역·예시 복사 시 실패)
- 등장 캐릭터의 `forbidden` 항목이 NEGATIVE 블록에 빠짐없이 들어갔는가
- 프롬프트에 임의의 HEX 색상값이나 로고 지시가 들어가지 않았는가
- 예상 Higgsfield 크레딧, 생성 클립 수, 재생성 상한이 기록되었는가
- 담당자가 위 비용 사용을 명시적으로 승인했는가
- 선택 스토리보드의 모든 장면에 `연결`과 `끝 포즈` 칸이 채워졌는가 (`extender` 표기에는 사유가 있는가)
- 배경이 같은 연속 컷의 배경·조명 서술이 문자 그대로 동일한가

## 컷 연결 검수 (`video-review.md`)

영상 검수에서 컷 경계를 **전환 지점마다 하나씩** 확인한다. 여기서 걸리지 않으면 컷 체인
규칙을 지켰는지 아무도 확인하지 않게 된다.

- 컷 N의 시작이 컷 N-1의 마지막 프레임과 이어지는가 — 캐릭터 위치·크기·색조·배경이 튀지 않는가
- 컷 경계에서 캐릭터 외형이 이탈하지 않았는가 (누적 열화 확인)
- `production-log.json`의 `video_clips`에 컷별 `link`·`start_image`·`prev`가 기록되었는가 (`node unsorted/scripts/check-production-gate.mjs <log> --stage final`로 확인한다)
- `extender`를 쓴 컷이 스토리보드에 표시된 예외 구간과 일치하는가 (표시 없는 사용은 실패)

경계가 튀는 컷을 발견하면 **뒤쪽 컷(N)의 번호**를 재생성 대상으로 기록한다. 원인이 앞 컷의
끝 포즈에 있으면 컷 N-1을 대상으로 기록하고, 재생성 전파는 다음 컷 하나까지로 제한한다
(`video-generator` 3단계).

영상 생성 후에는 자동 검수로 통과한 클립을 잠그고, 실패한 클립 번호만 `video-review.md`에 재생성 대상으로 기록한다. 정상 클립의 재생성은 금지한다.

## 예외 처리

| 상황 | 처리 |
|---|---|
| 필수 파일 누락 | 해당 단계 검수 스킵, 누락된 파일명 기록 |
| 가이드 데이터 없음 | 검수 불가, 가이드 연결 요청 |
| 영상 API 오류 | 오류 원인과 재시도 가능 여부를 production-log.json 에 기록 |
| 캐릭터 외형 변형 감지 | 해당 장면만 재생성할 수 있도록 장면 번호 기록 |
| 컷 경계 불연속 감지 | 원인 컷(앞 컷의 끝 포즈 / 뒤 컷의 시작) 번호와 함께 기록. 전파는 다음 컷 하나까지 |
| 마지막 프레임 파일 누락 | 해당 컷을 검수 불가로 표시하고 클립 재생성과 프레임 재추출을 요청 |
| 저작권 위험 감지 | 대체 가능한 음원·폰트·이미지 제안 기록 |
