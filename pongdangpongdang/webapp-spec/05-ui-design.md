# ⑤ UI 디자인 규칙

- 문서 상태: 확정 v1.0 · ⑥ 클릭형 프로토타입 반영
- 방향: 업무용의 신뢰감 + 초보자를 배려하는 친절함
- 우선 환경: 콘텐츠 담당자 PC, 콘텐츠 팀장 PC·모바일
- 전제: 사용자가 제공한 부라봉 이미지와 공식 부라봉 08·09·10쪽을 기준으로 작업용 UI 팔레트를 구성한다. 공식 HEX가 별도로 확인된 것은 아니므로 아래 값은 `첨부 이미지에서 추출한 작업용 색상`으로 기록한다.

## 1. 디자인 원칙

1. **행동이 먼저 보인다.** 화면 제목보다 현재 상태와 다음 행동을 더 가까이 배치한다.
2. **색상만으로 뜻을 전달하지 않는다.** 아이콘, 상태명, 단계 번호, 설명을 함께 쓴다.
3. **승인과 실행을 분리한다.** 승인 버튼을 누른 직후 유료 생성이나 외부 게시를 자동 실행하지 않는다.
4. **잠긴 기능도 보이게 한다.** 버튼을 숨기지 않고 잠금 이유와 해제 조건을 표시한다.
5. **근거를 가까이 둔다.** 검수 판정·승인·비용 경고는 원본, 대상 버전, 계산 근거와 함께 보여 준다.
6. **초보자에게 안전한 기본값을 준다.** 선택하지 않으면 게시·삭제·비용 발생이 일어나지 않는다.
7. **캐릭터 이미지는 장식으로 쓰지 않는다.** 프로젝트 미리보기와 공식 가이드 확인 영역에서만 승인된 원본·결과물을 사용한다.

## 2. 시각 토큰

### 2.1 기준 색상

| 용도 | 밝은 화면 기준 | 출처·사용 규칙 |
|---|---|---|
| 기본 글자 | `#341F0B` 짙은 갈색 | 윤곽·눈·입 색 기반. 제목·본문·라벨·상태 배지에 공통 사용 |
| 기본 행동 | 배경 `#EDA95D` + 글자 `#341F0B` | 몸체 색 기반. 화면당 하나의 기본 버튼과 현재 선택 상태 |
| 브랜드 강조 | `#EDA95D` 한라봉 주황 | 몸체 색 기반. 짙은 갈색 글자와 사용 |
| 보조 강조 | `#E37731` 볼 주황 | 선택·비용·제작 관련 강조. 큰 면적에는 사용하지 않음 |
| 완료·통과 | `#3E7135` 잎 녹색 | 잎 색 기반. 체크 아이콘 + `통과` 문구 |
| 페이지 배경 | `#FFFFFF` 흰색 | 전체 앱과 작업 영역의 기본 배경 |
| 카드·패널 | `#FFFFFF` | 입력·승인·결과 영역 |
| 보조 글자 | `#341F0B` | 색은 유지하고 글자 크기·굵기·배치로 정보 위계를 구분 |
| 테두리 | `#DEC9AD` | 크림·갈색 계열 구획, 표, 입력 필드 |
| 조건부 통과·주의 | `#9A6700` | 삼각형 아이콘 + 조건 설명 |
| 실패·차단 | `#B42318` | X 아이콘 + 실패 근거·복구 행동 |
| 확인 필요 | `#3157A4` | 물음표 아이콘 + 담당자 확인 요청 |

첨부 이미지의 대표 픽셀 군은 `#EDA95D`, `#E37731`, `#341F0B`, `#3E7135`로 확인했다. 이 값은 웹앱의 작업용 팔레트이며 공식 캐릭터 HEX라고 표기하지 않는다. 실패·차단·확인 필요는 배경색과 아이콘에 의미 색을 사용하되 글씨는 `#341F0B`로 통일한다. 위험 실행 버튼만 충분한 대비를 위해 흰색 글자를 허용한다.

### 2.2 승인 유형 고유 표현

승인 종류와 승인 상태는 다른 시각 속성으로 표현한다. 승인 종류는 카드의 왼쪽 강조선·아이콘·단계 번호로, 상태는 별도 배지로 표시한다.

| 승인 유형 | 고유 색 | 아이콘 | 고정 이름 | 승인 효과 문구 |
|---|---|---|---|---|
| 제작·비용 승인 | 볼 주황 `#E37731` | `wallet-cards` | `1단계 · 제작·비용 승인` | 유료 영상 생성 기능이 열립니다 |
| 최종 영상 승인 | 중간 갈색 `#7D5C3A` | `badge-check` | `2단계 · 최종 영상 승인` | 이 영상 버전이 최종본으로 확정됩니다 |
| 배포 승인 | 잎 녹색 `#3E7135` | `send` | `3단계 · 배포 승인` | 승인된 조건으로 게시·예약할 수 있습니다 |

승인 카드 안에서 `대기`, `승인됨`, `수정 요청`, `보류`, `무효` 상태는 공통 상태 배지로 표시한다. 예를 들어 갈색 카드라고 해서 승인 완료를 뜻하지 않는다.

### 2.3 글꼴·크기

- 글꼴: `Pretendard`, `Apple SD Gothic Neo`, `Noto Sans KR`, 시스템 sans-serif 순서
- 화면 제목: 24px, 600
- 영역 제목: 18px, 600
- 본문·입력: 16px, 400
- 버튼·라벨: 15px, 500
- 보조 설명: 13~14px, 400. 필수 정보에는 사용하지 않는다.
- 숫자와 비용: tabular 숫자를 사용해 자리 변화를 쉽게 비교한다.

### 2.4 간격·형태

- 4px 단위 간격 체계: 4, 8, 12, 16, 24, 32
- 일반 카드 모서리: 12px
- 입력·버튼 모서리: 8px
- 상태 배지: 둥근 캡슐 형태, 한 줄 유지
- 그림자는 최소화하고 테두리와 배경 차이로 구획한다.
- PC 본문 최대 폭은 1200px로 두고 긴 문서 편집 영역은 760~840px를 유지한다.

## 3. 단계 표시

상단에는 15단계를 모두 작은 글자로 나열하지 않고 5개 묶음 진행 표시를 사용한다.

| 상태 | 표현 |
|---|---|
| 완료 묶음 | 체크 아이콘, 잎 녹색, 완료 시각을 도움말로 제공 |
| 현재 묶음 | 진한 기본색 배경, `현재` 문구, 현재 세부 단계 표시 |
| 다음 묶음 | 중립 회색, 잠금 아이콘과 해제 조건 |
| 실패로 중단 | 빨간 점 또는 아이콘, `수정 필요` 문구 |
| 승인 대기 | 시계 아이콘, 승인 종류와 담당자 표시 |

프로젝트 내부 왼쪽 단계 메뉴에서는 세부 15단계를 보여 주되 완료한 묶음은 접는다.

## 4. 상태 배지

배지는 `[아이콘] 상태명` 구조를 사용한다.

| 상태 | 아이콘 | 배경 성격 | 사용 예 |
|---|---|---|---|
| 작성 중 | 연필 | 중립 | 기획안 작성 중 |
| 자동 처리 중 | 회전 표시 | 파랑 | 영상 생성 중 4/7 |
| 담당자 대기 | 시계 | 노랑 | 팀장 승인 대기 |
| 통과 | 체크 원 | 녹색 | 기획 검수 통과 |
| 조건부 통과 | 경고 삼각형 | 노랑 | 수정 후 재검수 |
| 실패 | X 원 | 빨강 | 캐릭터 외형 불일치 |
| 확인 필요 | 물음표 원 | 파랑 | 공식 근거 확인 필요 |
| 승인 무효 | 연결 끊김 | 빨강 테두리 | 문안 변경으로 재승인 필요 |
| 잠김 | 자물쇠 | 회색 | 제작 승인 전 영상 생성 불가 |

`조건부 통과` 옆에는 남은 수정 항목 수를 함께 표시한다. `실패`에는 실패 근거가 있는 위치로 이동하는 링크를 제공한다.

## 5. 승인 대기 표시

### 승인함 카드

한 카드에는 다음 정보만 우선 표시한다.

- 승인 종류의 단계 번호·고정 이름·아이콘
- 프로젝트명과 요청자
- 대상 버전과 요청 시각
- 승인 전에 반드시 볼 핵심 정보
- 위험 또는 변경 배지
- `검토 시작` 버튼

팀장 모바일에서는 최종 승인과 배포 승인을 같은 카드에 합치지 않는다. 한 승인을 완료해도 다음 승인 화면으로 자동 이동하지 않는다.

### 승인 상세

1. 승인 효과와 외부 영향
2. 대상 결과물 실제 확인
3. 검수·버전·비용·변경 요약
4. 필수 확인 체크
5. 승인 의견
6. `수정 요청`과 승인 버튼

승인 버튼 문구에 유형을 생략하지 않는다. `승인` 대신 `최종 영상 승인`, `이 조건으로 배포 승인`처럼 쓴다.

## 6. 자동 검수 결과

검수 화면의 우선순위는 점수가 아니라 위험 항목이다.

1. 자동 실패 항목
2. 필수 수정 항목
3. 담당자 확인 필요 항목
4. 통과 항목

각 항목은 다음 구조를 사용한다.

- 판정과 위험도
- 대상 산출물·장면·버전
- 위반 내용
- 공식 가이드 근거와 확인 페이지
- 수정 제안
- `원문 보기`, `원본과 비교`, `수정 위치로 이동`

종합 점수는 참고 정보로만 표시하며 점수가 높아도 자동 실패 항목이 있으면 `실패`를 우선한다.

## 7. 비용·크레딧 표시

비용은 `예상 → 승인 한도 → 실제 사용 → 추가 예상` 순서로 보여 준다.

| 사용 비율 | 표현 | 행동 |
|---:|---|---|
| 0~69% | 중립 진행 막대 | 일반 안내 |
| 70~89% | 주의 문구 | 남은 크레딧과 재생성 횟수 표시 |
| 90~99% | 강한 경고 | 다음 호출 예상 비용을 먼저 표시 |
| 100% 이상 | 빨간 차단 상태 | 추가 유료 호출 잠금, 수정 금액 재승인 |

항상 함께 표시할 항목:

- 예상 비용(원)과 예상 크레딧
- 승인 한도와 실제 사용액
- 생성 클립 수와 성공·실패 수
- 승인된 재생성 상한과 사용 횟수
- 마지막 외부 호출의 비용과 요청 ID

크레딧을 원화처럼 보이게 하지 않고 `48 cr`과 `₩12,400`을 나란히 구분한다.

## 8. 버튼 규칙

| 버튼 유형 | 사용 | 규칙 |
|---|---|---|
| 기본 | 현재 화면에서 가장 중요한 다음 행동 | 화면당 하나, 동사+대상 명시 |
| 보조 | 저장, 비교, 미리보기, 수정 요청 | 기본 버튼보다 낮은 강조 |
| 텍스트 | 도움말, 상세 보기, 이전 단계 | 주변 흐름을 방해하지 않음 |
| 위험 | 게시 철회, 삭제, 승인 회수 | 기본 행동으로 두지 않고 확인창 사용 |
| 잠김 | 조건을 충족하지 못한 실행 | 숨기지 않고 잠금 이유 표시 |

좋은 버튼 문구:

- `기획안 확정`
- `비용을 확인하고 제작 승인`
- `3번 장면만 재시도`
- `팀장에게 최종 승인 요청`
- `이 조건으로 배포 승인`

피해야 할 문구: `확인`, `진행`, `완료`, `실행`처럼 대상과 결과를 알 수 없는 표현.

## 9. 위험 작업 확인창

### 9.1 제작·비용 승인

- 선택 스토리보드와 버전
- 예상 비용·크레딧·클립 수·재생성 상한
- 승인으로 유료 생성이 열림을 명시
- 비용 확인 체크 후 승인 활성화

### 9.2 유료 영상 생성

- 이번 호출의 대상 장면과 예상 크레딧
- 승인 잔여 한도
- 공식 PNG·프롬프트 검증 상태
- `승인 범위 안에서 영상 생성` 버튼

### 9.3 게시·예약

- 영상 버전·해시
- 플랫폼·계정
- 캡션·공개 범위·KST 시각
- 배포 승인과 현재 값 일치 여부
- `승인된 조건으로 예약` 버튼

### 9.4 게시 후 철회

- 삭제보다 `비공개 전환`을 먼저 제안
- 현재 URL·플랫폼·성과·영향 표시
- 철회 요청 사유 필수
- 콘텐츠 팀장의 별도 철회 승인
- 영구 삭제 선택 시 프로젝트명을 다시 입력하도록 요구

## 10. 도움말과 입력 예시

도움말은 세 수준으로 제공한다.

1. **항상 보이는 짧은 설명:** 필드 아래 한 문장
2. **좋은 예/피해야 할 예:** 초보자의 실수가 잦은 입력에만 제공
3. **상세 도움말:** 공식 근거, 용어 설명, 파일 규칙을 펼쳐 보기

예:

```text
핵심 상황 *
[비 오는 날 우산을 두고 벌어지는 작은 소동]
좋은 예: 공식 설정 안에서 벌어지는 일상 사건
피해야 할 예: 공식 가이드에 없는 과거·능력·관계를 확정하는 내용
```

오류 문구는 `잘못되었습니다`가 아니라 원인과 수정 방법을 쓴다.

```text
영상 길이가 63초입니다. 4초 이상 줄여야 다음 단계로 진행할 수 있습니다.
```

## 11. 빈 화면·로딩·오류·반려·권한 없음

| 상태 | 반드시 보여 줄 내용 | 기본 행동 |
|---|---|---|
| 빈 화면 | 아직 없는 결과물, 필요한 이유, 준비할 입력·파일 | 첫 결과물 만들기 |
| 로딩 | 실제 진행 단계, 완료 수/전체 수, 비용 발생 여부, 화면 이탈 가능 여부 | 백그라운드로 두기 |
| 오류 | 원인, 비용 발생 여부, 보존된 결과, 재시도 가능 여부, 오류 ID | 안전하게 재시도 |
| 반려 | 승인 종류, 반려자, 사유, 대상 버전·필드, 재제출 조건 | 수정 위치로 이동 |
| 권한 없음 | 읽기 범위, 실제 담당자, 요청 상태 | 담당자에게 요청 |
| 승인 무효 | 승인 후 변경된 값, 기존 승인 대상, 재승인 범위 | 변경 확인 후 재승인 요청 |

로딩 중 예상 시간을 근거 없이 표시하지 않는다. 외부 서비스가 제공하는 신뢰 가능한 예상 시간이 있을 때만 범위로 보여 준다.

## 12. 반응형 규칙

### 콘텐츠 담당자 PC

- 왼쪽: 프로젝트 세부 단계
- 중앙: 현재 작업 본문
- 오른쪽: 승인·검수·비용·파일 요약
- 하단: 이전, 임시 저장, 기본 행동

### 콘텐츠 팀장 모바일

- 승인 종류와 프로젝트명
- 실제 영상 또는 배포 조건
- 검수·버전·비용 요약
- 필수 확인 체크
- 수정 요청과 승인 버튼

모바일 터치 영역은 최소 44×44px로 하고, 승인 버튼을 보기 전에 핵심 결과 확인 영역을 거치게 한다.

## 13. 접근성·신뢰성

- 본문 대비 4.5:1 이상, 큰 글자와 아이콘 3:1 이상
- 상태는 색상+아이콘+텍스트로 표시
- 키보드만으로 모든 입력·비교·승인 가능
- 포커스 테두리를 제거하지 않음
- 동적 검수·생성 상태는 보조 기술에 알림
- 애니메이션은 반복하지 않고 동작 줄이기 설정을 존중
- 테이블·타임라인의 날짜와 비용은 화면 읽기 순서를 유지
- 승인·게시·철회 후 결과와 감사 기록 ID를 즉시 표시

## 14. 확정·제안 구분

### 확정 사항

- 제작·비용, 최종 영상, 배포 승인을 이름·번호·아이콘·색으로 구분한다.
- 검수 결과는 통과·조건부 통과·실패·확인 필요와 근거를 표시한다.
- 비용·크레딧·클립·재생성을 동시에 보여 준다.
- 잠긴 버튼에는 해제 조건을 표시한다.
- 게시 후 철회는 팀장의 별도 확인과 위험 작업 확인창을 사용한다.

### 설계 제안

- 흰색 배경과 짙은 갈색 `#341F0B` 글씨를 기본으로 하고, 기본 행동에는 몸체 주황 `#EDA95D` 배경을 사용한다.
- 승인 유형은 볼 주황·중간 갈색·잎 녹색의 고유 색과 단계 번호를 사용한다.
- 게시 철회 시 비공개 전환을 기본 선택으로 제안한다.
