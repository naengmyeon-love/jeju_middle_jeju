# ④ 핵심 화면 와이어프레임

- 문서 상태: 확정 v1.0
- 기준 해상도: 콘텐츠 담당자 PC 1440px 이상, 팀장 모바일 360px 이상
- 표현 단계: 구조·정보 우선순위 검증용 저해상도 와이어프레임

## 1. 공통 프로젝트 화면

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 로고   홈  프로젝트  승인함  배포 일정  제작 이력          알림  사용자     │
├──────────────────────────────────────────────────────────────────────────────┤
│ 프로젝트명                  8/15 제작·비용 승인     담당자: 콘텐츠 담당자   │
│ ● 준비 ─ ● 기획·연출 ─ ● 사전 검수 ─ ○ 영상 ─ ○ 배포                     │
├───────────────────────────────────────────────────────┬──────────────────────┤
│ 현재 상태와 다음 행동                                 │ 프로젝트 요약        │
│ [현재] 제작비 승인 대기                               │ 제작 승인  대기      │
│ 선택안·비용을 확인하면 영상 생성 기능이 열립니다.     │ 최종 승인  요청 전   │
│                                                       │ 배포 승인  요청 전   │
│ 단계별 본문                                           │ 검수 결과  통과      │
│ - 입력·문서·미리보기·비교·검수·승인 내용              │ 비용  ₩12,400/48cr   │
│ - 필요한 파일과 누락 상태                             │ 클립  6 / 재생성 2   │
│ - 근거·버전·담당자                                    │ 필요한 파일  9/9     │
│                                                       │ 최근 변경            │
├───────────────────────────────────────────────────────┴──────────────────────┤
│ 이전 단계          임시 저장                [현재 단계의 기본 행동]          │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 항상 고정되는 정보

- 현재 단계와 전체 진행 위치
- 사용자가 지금 해야 할 한 가지 행동
- 현재 담당자와 다음 담당자
- 제작·비용, 최종 영상, 배포 승인 상태
- 기획 검수와 영상 검수 상태
- 예상·실제 비용, 크레딧, 클립 수, 재생성 횟수
- 필수 파일 준비 상태와 공식 PNG 연결 여부
- 대상 버전과 마지막 변경 시각

## 2. 콘텐츠 담당자 대시보드

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 오늘 해야 할 일                                      [+ 새 프로젝트]        │
├───────────────────────────────┬──────────────────────────────────────────────┤
│ 다음 작업                     │ 진행이 멈춘 항목                            │
│ 1. 제작비 다시 승인  [열기]   │ 비용 상한 도달 · 실패 클립 1개 [해결]      │
│ 2. 영상 검수 확인    [열기]   │ 조건부 통과 · 말투 수정 필요   [수정]      │
├───────────────────────────────┼──────────────────────────────────────────────┤
│ 내 제작·비용 승인 대기        │ 다가오는 배포                               │
│ 프로젝트 / 예상비 / 요청 시각 │ 플랫폼 / 예약 시각 / 배포 승인 상태        │
└───────────────────────────────┴──────────────────────────────────────────────┘
```

기본 행동은 가장 시급하고 진행 가능한 항목 하나에만 강조한다. 실패 항목은 일반 할 일과 분리한다.

## 12. 공통 예외 상태

| 상태 | 화면 구성 | 기본 행동 |
|---|---|---|
| 빈 화면 | 무엇이 아직 없는지, 왜 필요한지, 만들면 열리는 단계, 필요한 파일 | `첫 결과물 만들기` 또는 `파일 연결` |
| 로딩 | 현재 수행 중인 작업, 완료된 수/전체 수, 예상이 아닌 실제 진행 단계, 안전하게 화면을 나가도 되는지 | `백그라운드로 두기` 또는 취소 가능한 경우만 `작업 취소` |
| 오류 | 원인, 비용 발생 여부, 보존된 결과, 재시도 가능 여부, 오류 ID | `안전하게 재시도` 또는 `연결 확인` |
| 반려 | 승인 종류, 반려자, 사유, 수정 대상 버전·필드, 재제출 조건 | `수정할 위치로 이동` |
| 권한 없음 | 읽기 가능 범위, 실행 권한이 있는 담당자, 현재 요청 상태 | `담당자에게 요청` 또는 `읽기 전용으로 보기` |
| 비용 초과 | 승인액·사용액·추가 예상액, 성공 클립, 중단 시점 | `수정 금액 확인 및 재승인` |
| 승인 무효 | 무엇이 승인 후 바뀌었는지, 기존 승인자·시각, 재승인 범위 | `변경 내용 확인 후 재승인 요청` |

## 13. 버튼 배치 규칙

- 화면당 강조 기본 버튼은 하나만 둔다.
- `승인`, `영상 생성`, `게시·예약`, `철회`는 서로 다른 확인 단계를 사용한다.
- 잠긴 버튼은 숨기지 않고 잠금 사유를 바로 아래에 표시한다.
- `수정 요청`은 승인 버튼과 같은 크기로 두되 시각적 우선순위는 낮춘다.
- `삭제·철회`는 기본 행동으로 배치하지 않는다.
- 모바일에서는 승인/수정 요청 버튼을 화면 하단에 연속 배치하되 콘텐츠를 가리지 않는다.

## 14. 와이어프레임 검증 기준

- 처음 접속한 사용자가 10초 안에 현재 단계와 다음 행동을 말할 수 있는가
- 제작·비용, 최종 영상, 배포 승인을 혼동하지 않는가
- 영상 생성 전에 비용과 재생성 상한을 인지하는가
- 검수 판정의 근거와 수정할 위치를 찾을 수 있는가
- 팀장이 모바일에서 실제 영상·문안·계정을 확인하고 승인하는가
- 게시 후 철회가 일반 예약 취소와 다른 작업임을 이해하는가
