## 중요 전제 — 이미지 검수 범위 제한

이번 프로젝트는 아직 스토리보드 장면 PNG를 생성하지 못한 상태다. `metadata/production-log.json`의
`approvals.production.status`가 `not_requested`(제작·비용 승인 미기록)이고, 이번 세션에서
`higgsfield` CLI 직접 호출이 권한 정책상 차단되어 `higgsfield-prompt-builder`의 사전 게이트를
충족하지 못했다(아래 "Higgsfield 사전 게이트" 절 참고). 따라서:

- **"이미지 문자 안전성", "이미지·스토리 일치", "이미지 연속성", "장면별 신체 특징 유지(이미지 기준)", "스토리보드 이미지 존재" 등 이미지 자체의 시각적 대조 검수 항목은 이번 회차에서 "미실시 — 이미지 미생성"으로 처리한다.**
- 대신 문서(기획안·시나리오·스토리보드 3안)에 서술된 텍스트와, 각 스토리보드에 기록된 **조립된 Higgsfield 프롬프트**를 `character-guide` 및 `image-generation-contract.json`과 대조하는 텍스트 기반 검수만 수행했다.
- 레퍼런스 페이지 PNG(`shared/references/pages/page-08.png`, `page-09.png`, `page-10.png`) 실물 파일 존재는 확인했으나, 각 스토리보드가 주장하는 "view_image로 직접 확인함" 절차 자체는 이번 검수에서 재현·검증하지 않았다(문서상 기록을 신뢰하되 별도 검증 표시는 하지 않음).

## 5. 조립된 Higgsfield 프롬프트 규칙 대조 (텍스트 기준)

각 스토리보드에 기록된 "조립된 프롬프트"를 `image-generation-contract.json`(v1.1)과 대조했다.

| 규칙 | 결과 | 근거 |
|---|---|---|
| camera: 단일 앵글 + 단일 샷 크기 | **조건부 통과** | A안(`front-facing full shot`/`three-quarter view medium shot`/`low-angle full shot`)과 B안(`front-facing extreme close-up`/`front-facing close-up`/`side-facing full shot`/`low-angle extreme close-up`)은 앵글+샷 크기가 명확히 분리되어 기재됨. **C안의 3장면(`wide establishing shot`/`wide shot`/`close-up`)은 명시적 카메라 앵글 용어(front-facing/side-facing/low-angle 등)가 빠져 있고 "wide"가 앵글인지 샷 크기 수식어인지 모호함** — 규칙 위반은 아니나 표기 명확성이 A/B안보다 낮음 |
| scene: 단일 순간 | 통과 | 전체 10개 장면 SCENE 블록에 `then`, `while`, `after` 등 시간 흐름 접속 표현 없음. "steps from a sun-lit trail into forest shade"(A-1), "walks alone along a quiet forest trail"(C-1) 등 동작 서술이 있으나 각 문서의 "정지 이미지 순간(선택 근거)" 항목에서 단일 정지 자세로 명시적으로 좁혀 서술했음을 확인 |
| lock_en 원문 유지 | 통과 | A안 장면1 CAST 블록을 `image-generation-contract.json`의 `boo-rabong.lock_en`과 1:1 대조한 결과 완전 일치(글자 단위). 요약·의역 없음 |
| forbidden 항목 NEGATIVE 블록 포함 | 통과 (근거 기반) | A안 장면1이 "global_negative_en 9항목 + boo-rabong forbidden_en 7항목, 총 16항목"으로 명기했으며, 이는 contract v1.1의 실제 항목 수(global 9개, boo-rabong forbidden_en 7개)와 정확히 일치. 단, 스토리보드 문서 자체에는 16항목 전문이 아니라 요약 표기만 있어 실제 CLI 호출 시 전문이 그대로 들어가는지는 실행 단계에서만 최종 확인 가능 | 실제 생성 실행 시 NEGATIVE 블록 전문이 누락 없이 포함되는지 1회 확인 필요 |
| 공식 레퍼런스 첨부 | 통과 | 전 10개 장면 모두 `page-08.png`, `page-09.png`, `page-10.png` 3개 레퍼런스 경로가 실행 명령(`--image` 인자)에 포함, 파일 실존 확인(`shared/references/pages/` 디렉터리에 3개 파일 모두 존재) | 없음 |

**게이트 판정: 생성 중단 (Higgsfield 미호출 유지)** — "담당자 스토리보드 선택", "예상 크레딧/클립 수/재생성 상한 기록", "비용 사용 명시적 승인" 3개 항목이 미충족이므로 `production-log.json`에 기록된 대로 이미지 생성을 진행하지 않는다.

## 자동 실패 트리거 점검

1. 캐릭터 공식 외형 훼손 — 텍스트 기준 미해당 (이미지 미생성으로 최종 확정 불가, 재검수 필요)
2. 캐릭터 성격/말투 중대 불일치 — 미해당
3. 양퐁당 해녀/물질 묘사 — 미해당(미등장)
4. 호꼬 대사 부여 — 미해당(미등장)
5. 부라봉 기억상실 이전 과거 확정 — 미해당
6. 공식 부정 관계 긍정 변경 — 미해당(단독 등장)
7. 공식 6인 외 캐릭터 등장 — 미해당
8. 임의 HEX 사용 — 미해당
9. 필수 스토리보드 장면 이미지 누락 — **해당하나 예외 처리**: 계획 단계 승인 대기 상태로 문서화되어 은폐 없이 명시됨(§ "필수 파일 누락" 예외 규정 적용, 자동 실패 대신 "미실시" 처리)
10. 직접적 상품 판매·구매 유도 — 미해당
11. 영상 길이 60초 이상 — 미해당(15초)
12. 저작권 침해 가능성 — 미해당(BGM/효과음 미확정 상태로 저작권 확인 조건이 문서에 명시됨)
13. 담당자 검수 누락 — 계획 승인(`approvals.planning`) 자체도 아직 `not_requested` 상태 (별도 승인 절차 필요, 이 검수 결과와 무관하게 담당자 승인 별도 진행 필요)

## 담당자 확인 필요 항목 (기존 문서에서 이관, 변경 없음)

1. 비자림 배경의 사용 허용 범위와 구체적 촬영 구역
2. 대사 및 화면 자막 문구 확정
3. 배경음악·효과음 사용 여부와 분위기
4. 게시 예정 플랫폼
5. 제작·비용 승인 및 3안 중 실제 제작에 쓸 스토리보드 선택
6. 예상 Higgsfield 크레딧·클립 수·재생성 상한 기록

## 수정 제안 요약 (경미)

1. B/C안 스토리보드에도 최소 1개 장면에서 전체 조립 프롬프트(STYLE~OUTPUT)를 노출해 CAST/NEGATIVE 블록의 lock_en·forbidden 완전 일치를 직접 대조 가능하게 할 것 (현재는 A안 장면1만 전문 노출)
2. C안 카메라 표기(`wide establishing shot`/`wide shot`/`close-up`)에 명시적 앵글 용어를 추가해 A/B안과 표기 일관성을 맞출 것
3. `production-log.json`의 `approvals.production`에 예상 크레딧·클립 수·재생성 상한을 기록할 것 (Higgsfield 게이트 미충족 항목)
